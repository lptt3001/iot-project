The generic insect detector is the improved YOLOv8 P2 (34,000 points), fine-tuned for blurred/dark camera images on 819 training examples over eight epochs, using recall-first confidence 0.075 selected by F3 on a separate degraded validation split; six-species identification still requires confidence 0.70 and class margin 0.15. Browser inference merges a full image with overlapping tiles. The decoder supports both the P2 output and the unchanged 8,400-point species output. Unknown objects require insect-detector evidence. These are experimental counts and species suggestions, not confirmed diagnoses. Evaluation details and hashes are in `ai/model.json` and `deliverables/PTIT_Camera_Recall_20261109/BAO_CAO.md`; metrics describe synthetic camera-degraded source data before species fusion, not independent field accuracy. This operating point has substantial false positives (test precision about 21.7%) and was chosen at the user's explicit preference to tolerate false detections. Generic boxes are labelled “Côn trùng”; species identification and fruit-tree alert eligibility remain strict. Existing successful images can be reanalysed locally with the current model without overwriting history. P2 is more expensive on CPU/WASM; allow time for model loading and tiled inference.

Obsolete generic inference bundles and duplicate archives have been removed. Historical P2 comparison evidence remains under `deliverables/PTIT_P2_CaiThien_20261109`. Only the current P2 detector and required six-species ONNX should be present in the deployed `ai/` directory. Docker's `app/static` model configuration is separate and unchanged.

New hardware photos enter a durable analysis queue. Every five minutes the Worker claims one job, runs the same P2 + six-species ONNX pipeline in a Cloudflare Browser Run session, and stores boxes/counts/model version in D1. This runs with the user's browser closed and PC off. A short-lived HttpOnly capability grants the cloud browser access only to its own photo and AI assets; it cannot access dashboard accounts or other photos. One leased job runs at a time, with up to three inference attempts. Failed processing stays visibly failed; it never becomes a zero-pest result. Historical images are not bulk-enqueued on migration.

Camera insect alerts support all six model species, each with an independent on/off selection and per-image threshold. An optional unknown-insect category has its own threshold and is off by default. A photo creates one web alert if at least one enabled category reaches its own threshold; counts are never added across categories. Alert details record all observed counts, the matching species/counts/thresholds, and the rule revision. The photo's crop is snapshotted when it arrives; changing the active crop does not relabel older photos. Deleted photos, obsolete analysis leases, photos received before a rule change, and photos without crop context cannot create a new alert. Result persistence and alert creation commit together. The unified Telegram queue fans out the same event to eligible recipients with existing deduplication and retries. An insect alert does not diagnose disease or prove damage to the selected crop.

The four profiles are guava, pomegranate, durian and pear. One station/soil probe monitors the selected location and crop; selecting four profiles is not four simultaneous sensor stations. `GET /api/rules` now returns an object with `active_crop`, `profile_revision`, `crop`, `crops` and `rules`; it is no longer the old generic-rule array. Admin-only `PUT /api/rules/profile` and `PUT /api/rules/:id` require a current revision and validate all parameters. Revision conflicts return 409. Saving rules or switching profiles clears cached conclusions, cancels obsolete pending advisories and restarts duration counting from activation time. Crop settings remain isolated.

Exactly three alert groups are available:

| Group | Measured evidence and default operational setting | Interpretation |
| --- | --- | --- |
| `soil_wet` | Two-point site-specific calibration; relative wet index >=85% for 120 observed minutes | Inspect waterlogging, irrigation, drainage and roots; not a root-rot diagnosis or volumetric water content |
| `humid_environment` | Guava/pomegranate: 25–30°C, RH >=85% for 60 min; durian: 24–30°C, RH >=85% for 60 min; pear: 15–25°C, RH >=85% for 120 min | Inspect crop-specific leaf/fruit symptoms; not a validated infection forecast |
| `pest_image` | Independent thresholds for six identified species and optional unknown insects, configurable per crop | Inspect insects and actual crop damage; not every model class is a fruit-tree pest |

The soil group remains `needs_calibration` until both real dry/wet ADC references (20–4075, at least 200 apart) are saved. Either ADC direction works. Saturated wet reference and dry reference define a relative index clamped to 0–100; no universal ADC-to-water conversion is assumed. Current ADC <=5 or >=4090 is rejected for risk evaluation. Capture-reference buttons only fill the form from a currently online station; the operator must prepare the corresponding soil condition and explicitly save. Recalibrate when moving the probe/soil.

The five-minute cron evaluates each sensor group independently using telemetry received within 2 minutes of observation, from the last 13 hours (maximum 6,000 rows). A missing/invalid required input, unmatched condition, or sampling gap >2 minutes breaks that group's run. Data before the latest profile activation/rule update does not count. DHT11 observations outside 0–50°C or 20–90% RH are rejected for these evaluations; RH 95% is not used as a supported trigger. Missing DHT does not prevent soil evaluation, and missing soil does not prevent air evaluation. Stale status shows insufficient data, not safety. Default cooldown is 360 minutes for each crop/group; web alerts persist without Telegram, and active recipients receive new qualifying events through the existing queue. Local browser previews and demo images never generate real pest advisories.

All configured numeric defaults are monitoring choices requiring field adjustment, not confirmed biological infection thresholds.
